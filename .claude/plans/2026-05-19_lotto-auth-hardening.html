로또 인증/관리 API 보호

작성일: 2026-05-19 · 대상: Market Pulse 로또 분석 연구소

왜 이 작업이 먼저인가

로또 분석 화면과 API는 이미 상당 부분 구현되어 있다. 다음 기능을 더 얹기 전에, 쓰기 API와 운영성 API가 공개 상태로 남아 있을 가능성을 정리해야 한다.

Risk

공개 쓰기 API

비로그인 사용자가 조합 저장/삭제나 분석 실행 API를 호출할 수 있으면 데이터 오염 위험이 있다.

Mismatch

사용자 조합 소유권

현재 구조는 내 조합이 사용자별 데이터인지 전역 데이터인지 명확하지 않다.

Goal

안전한 기준선

조회는 공개, 개인 데이터는 로그인, 운영 실행은 ADMIN으로 분리한다.

기획-구현-검증 흐름

1. 기획 HTML 기획서와 spec.md로 범위, 비범위, AC를 고정한다.
2. 승인 유저가 범위와 결정사항을 확인한다.
3. 구현 backend/frontend 에이전트가 spec 기준으로 수정한다.
4. 검증 AC 기준으로 PASS/FAIL을 판정하고 FAIL이면 재기획한다.

접근 제어 설계

API 권한 이유
GET /api/lotto/latest, /rounds, /analysis, /stats PUBLIC 분석 조회 화면은 공개 기능이다.
POST /api/lotto/combo, GET /api/lotto/combo, DELETE /api/lotto/combo/{id} AUTH 내 조합은 개인 데이터이므로 로그인 사용자에게 귀속한다.
POST /api/lotto/analyze, /collect, /bulk-results, /analyze-all, /result ADMIN 데이터 생성/대량 변경/운영 실행 API이므로 관리자만 허용한다.
POST/PATCH/DELETE /api/lotto/comment/** AUTH 댓글 작성, 수정, 삭제는 기존 정책대로 로그인 필요.

구현 범위

Backend

  • SecurityConfig에서 로또 API 권한을 명시적으로 분리
  • 조합 저장/조회/삭제에 Authentication.getName() 반영
  • lotto_user_combo에 사용자 식별 컬럼 추가 검토
  • 번호 6개, 1~45, 중복 없음 검증

Frontend

  • 비로그인 상태에서 내 조합 저장/삭제 시 로그인 흐름으로 연결
  • 공개 분석 조회 실패와 내 조합 조회 실패를 분리
  • 기존 apiClient 401 처리 흐름 유지

결정 필요 사항

항목 선택지 권장
기존 저장 조합 처리 숨김 / 특정 계정 귀속 / 초기화 NULL legacy로 남기고 일반 사용자에게 숨김
사용자 식별 키 username / user_id 현재 인증 구조에 맞춰 username 1차 적용
비로그인 조합 조회 401 / 빈 배열 API는 401, 프론트에서 비로그인 시 호출하지 않음

검증 기준

  • 비로그인 사용자는 POST /api/lotto/combo 호출 시 401을 받는다.
  • 로그인 사용자는 자기 조합을 저장, 조회, 삭제할 수 있다.
  • 일반 USER는 POST /api/lotto/analyze 호출 시 403을 받는다.
  • ADMIN은 관리성 API를 실행할 수 있다.
  • 공개 로또 조회 API는 비로그인 상태에서도 동작한다.
  • 프론트 빌드와 백엔드 컴파일/테스트가 성공한다.
