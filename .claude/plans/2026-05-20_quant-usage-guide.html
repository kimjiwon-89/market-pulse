퀀트 백테스팅 사용법

Market Pulse의 KRX 히스토리컬 데이터 기반 퀀트 전략 비교 화면과 API 사용 절차

작동 구조

퀀트 기능은 KRX 데이터를 DB에 저장한 뒤, 저장된 가격 시계열로 전략별 백테스트를 실행하고 결과를 화면에 시각화한다.

1. KRX 수집

market_daily_price에 날짜별 가격 데이터 저장

2. 전략 등록

앱 기동 시 5개 기본 전략을 quant_strategy에 자동 등록

3. 백테스트

기간과 전략을 선택하면 서버가 결과를 계산하거나 캐시 조회

4. 시각화

/quant에서 수익률 차트, 성과 카드, 매매 로그 표시

현재 구현 상태

현재 버전은 기능 흐름을 연결한 MVP다. API, DB 저장, 화면 렌더링은 들어갔고 전략 계산은 단순화된 1차 모델이다.

다음 개선 단계에서는 월별 리밸런싱, 다종목 포트폴리오 평가, 수수료·세금 누적 계산을 더 정교하게 확장하면 된다.

처음 사용할 때

  1. 백엔드 서버를 실행한다. 서버 기동 시 quant 테이블 4종과 기본 전략 5개가 자동 준비된다.
  2. 관리자 계정으로 로그인한다.
  3. 초기 히스토리 데이터를 수동 수집한다.
  4. /quant 화면에서 기간과 전략을 선택해 결과를 확인한다.

전체 데이터 수집

dataType=ALL은 KOSPI/KOSDAQ 지수, KOSPI/KOSDAQ 주식, 채권, 금 데이터를 모두 수집한다.

POST /api/quant/collect?from=20200101&to=20200110&dataType=ALL

10일 이하는 동기 처리되고, 더 긴 기간은 백그라운드 수집으로 시작된다.

수집 상태 확인

긴 기간 수집 중에는 상태 API로 진행률을 확인한다.

GET /api/quant/collect/status
필드의미
statusIDLE, RUNNING, DONE, ERROR
progress0~1 사이 진행률
processedDates처리한 날짜 수
totalDates전체 대상 날짜 수
latestDate마지막 처리 날짜

자동 수집

매주 월~금 오후 4시에 전일 기준 전체 데이터 수집이 자동 실행된다.

@Scheduled(cron = "0 0 16 * * MON-FRI")
초기 5년치 같은 대량 backfill은 자동 기동이 아니라 ADMIN 수동 API로 실행한다. 서버 시작이 오래 막히는 것을 피하기 위한 구조다.

/quant 화면 사용법

  1. 좌측 또는 하단 네비게이션에서 퀀트 백테스팅을 연다.
  2. 기간 프리셋 또는 날짜 입력으로 조회 기간을 선택한다.
  3. 전략 비교 탭에서는 5개 전략과 KOSPI/KOSDAQ 벤치마크를 한 차트에서 비교한다.
  4. 개별 전략 탭을 누르면 해당 전략의 성과 카드, 자산 비중, 매매 시그널을 확인한다.

전략 비교 탭

서버가 /api/quant/performance를 호출해 모든 전략의 누적 성과를 가져온다.

  • KOSPI 벤치마크
  • KOSDAQ 벤치마크
  • 이동평균 돌파
  • 모멘텀
  • 섹터 로테이션
  • 자산배분
  • 변동성 조절

개별 전략 탭

서버가 /api/quant/backtest와 /api/quant/trades를 호출한다.

  • 총수익률, 최대낙폭, 샤프비율, 총거래횟수 표시
  • 현재 자산 비중 도넛 차트 표시
  • BUY/SELL 매매 로그 표시
  • 주식 종목명 클릭 시 /stock/:code로 이동

전략 목록

GET /api/quant/strategies

응답에는 id, name, nameEn, assetType, rebalanceCycle, params가 포함된다.

전략 비교

GET /api/quant/performance?from=20200101&to=20251231

5개 전략 결과와 KOSPI/KOSDAQ 벤치마크 시계열을 함께 반환한다.

개별 백테스트

GET /api/quant/backtest?strategyId=1&from=20200101&to=20251231

같은 파라미터로 다시 조회하면 quant_backtest_result에 저장된 결과를 재사용한다.

매매 로그

GET /api/quant/trades?strategyId=1&from=20200101&to=20251231&page=0&size=50

tradeType=BUY 또는 tradeType=SELL 필터를 추가할 수 있다.

주의사항

현재 전략 엔진은 1차 MVP다. 데이터 수집, API, DB 캐시, 화면 흐름을 먼저 연결했고, 전략별 리밸런싱 정밀도는 다음 단계에서 고도화 대상이다.

데이터가 없을 때

차트가 비어 있거나 백테스트 데이터 없음이 보이면 먼저 해당 기간의 KRX 데이터를 수집해야 한다.

POST /api/quant/collect?from=20200101&to=20200131&dataType=ALL

대량 수집

전체 5년치 수집은 오래 걸릴 수 있다. KRX API를 날짜별로 호출하고 500ms 간격으로 스로틀링한다.

처음에는 1개월 단위로 테스트한 뒤 기간을 넓히는 편이 안전하다.

권한

수집 API는 ADMIN 전용이다. 일반 조회 API는 공개다.

기능권한
전략 조회, 백테스트, 성과 비교, 매매 로그공개
데이터 수집, 수집 상태 조회ADMIN

다음 개선 후보

  • ADMIN 화면에 데이터 수집 버튼과 진행률 표시 추가
  • 월별 리밸런싱을 실제 다종목 포트폴리오 단위로 계산
  • 수수료와 매도세를 모든 거래에 누적 반영
  • 백테스트 캐시 무효화 또는 재계산 버튼 추가
  • 모델별 포트폴리오 비중을 동일가중이 아닌 점수·시총·시장상황 기반으로 차등 적용
  • 약한 시장 구간에는 현금 비중을 높이는 방어 리밸런싱 적용
