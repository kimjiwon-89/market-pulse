기능 목적

KRX Open API의 무료 히스토리컬 데이터(2010년~)를 활용해 5가지 퀀트 전략을 백테스팅하고, 누적 수익률·MDD·샤프 비율 등 성과 지표를 시각적으로 비교하는 모의투자 대시보드. 코드를 몰라도 "어떤 전략이 언제 잘 먹혔는가"를 직관적으로 파악할 수 있게 한다.

5가지 퀀트 전략
1. 이동평균 돌파 지수 추종
KOSPI 지수 기반. 20일선이 60일선을 돌파하면 매수(골든크로스), 반대이면 매도(데드크로스). 지수 ETF 1종 포지션, 현금 vs 시장 비중 0/1 전략.
KOSPI 지수 20일/60일 MA 신호 발생 시 거래
2. 모멘텀 개별종목
유가증권 전종목 중 전월 수익률 상위 20개 종목을 매월 첫 거래일 동일가중으로 편입. 당월 말 전량 매도 후 차월 상위 20개로 리밸런싱.
KOSPI 종목 월별 리밸런싱 상위 20종목
3. 섹터 로테이션 개별종목
KRX 업종 기준 최근 1개월 수익률 상위 3개 섹터 집중 투자. 매월 리밸런싱, 섹터 내 시가총액 상위 5종목 편입.
업종별 수익률 Top 3 섹터 월별 리밸런싱
4. 자산배분 멀티에셋
KOSPI 60% + 국채 30% + 금 현물 10% 분산. 분기마다 목표 비중으로 리밸런싱. 변동성 낮고 안정적인 절대수익 추구.
KOSPI + 국채 + 금 60/30/10 비중 분기 리밸런싱
5. 변동성 조절 다이나믹
KOSPI 20일 변동성(표준편차) 모니터링. 임계값(15%) 초과 시 채권 비중 ↑(80%), 하락 시 주식 ↑(70%). 시장 공포 시 자동 방어 포지션.
변동성 임계값 15% 주식/채권 동적 전환 일별 리밸런싱
배경 & 제약 사항
KRX API 무료 티어 — 기준일(basDd) 단위 조회. 하루 1개 날짜씩 호출해야 하므로 대량 수집은 스로틀링(500ms 간격) 필수. 초기 5년치(약 1,250 영업일)를 관리자 API로 수집한 뒤 이후 매일 자동 갱신.
백테스팅 엔진 — 서버사이드(Java)에서 실행. 프론트는 결과 조회·시각화 전담. 실행 시간이 길 수 있으므로(수초~수십초) 비동기 처리 필요.
거래 비용 모델 — 간략화: 매수/매도 각 0.015% 수수료 적용, 슬리피지 없음. 세금(0.18% 증권거래세)은 매도 시 적용.

신규 테이블 4개. 기존 테이블(users, investor_memo, stock_master 등)과 충돌 없음. psql로 직접 실행 필요 — data.sql은 참고용.
1. market_daily_price — KRX 일별 OHLCV 히스토리
CREATE TABLE market_daily_price (
    id           BIGSERIAL    PRIMARY KEY,
    trade_date   DATE         NOT NULL,
    asset_code   VARCHAR(20)  NOT NULL,   -- 종목코드 또는 지수코드 (KOSPI, BOND_3Y, GOLD 등)
    asset_type   VARCHAR(10)  NOT NULL,   -- STOCK | INDEX | BOND | GOLD | ETF
    asset_name   VARCHAR(100),
    open_price   NUMERIC(18,4),
    high_price   NUMERIC(18,4),
    low_price    NUMERIC(18,4),
    close_price  NUMERIC(18,4) NOT NULL,
    volume       BIGINT,
    market_cap   BIGINT,                  -- 시가총액 (STOCK 전용, 원 단위)
    sector       VARCHAR(100),            -- 업종 (STOCK 전용)
    ytm          NUMERIC(8,4),            -- 채권 수익률 (BOND 전용)
    created_at   TIMESTAMP    DEFAULT NOW(),
    CONSTRAINT uq_market_daily_price UNIQUE (trade_date, asset_code, asset_type)
);

CREATE INDEX idx_mdp_date_type ON market_daily_price(trade_date, asset_type);
CREATE INDEX idx_mdp_code_date ON market_daily_price(asset_code, trade_date);
KRX 엔드포인트별 asset_type 매핑: stk_bydd_trd → STOCK, kospi_dd_trd / kosdaq_dd_trd → INDEX, kts_bydd_trd → BOND, gold_bydd_trd → GOLD, etf_bydd_trd → ETF
용량 추산 — 유가증권 약 900종목 + 코스닥 약 1,600종목 + 지수/채권/금 10개 = 약 2,510개 자산 × 250일 × 5년 = 약 314만 행 × 약 200B ≈ 630MB. PostgreSQL 허용 범위. (초기에는 지수/채권/금 + KOSPI 상위 300종목으로 제한 가능)
2. quant_strategy — 전략 메타
CREATE TABLE quant_strategy (
    id              BIGSERIAL    PRIMARY KEY,
    name            VARCHAR(100) NOT NULL,
    name_en         VARCHAR(50)  NOT NULL UNIQUE,  -- MA_CROSSOVER | MOMENTUM | SECTOR_ROTATION | ASSET_ALLOCATION | VOLATILITY_ADJUST
    description     TEXT,
    asset_type      VARCHAR(10)  NOT NULL,          -- INDEX | STOCK | MULTI
    rebalance_cycle VARCHAR(20)  NOT NULL,          -- SIGNAL | MONTHLY | QUARTERLY | DAILY
    params          JSONB,                          -- 전략별 파라미터
    is_active       BOOLEAN      DEFAULT TRUE,
    created_at      TIMESTAMP    DEFAULT NOW()
);
앱 시작 시 QuantStrategyInitRunner가 5개 기본 전략을 INSERT (없으면). params 예시: {"shortMa":20,"longMa":60}, {"topN":20,"lookbackDays":21}
3. quant_backtest_result — 날짜별 포트폴리오 가치
CREATE TABLE quant_backtest_result (
    id             BIGSERIAL    PRIMARY KEY,
    strategy_id    BIGINT       NOT NULL REFERENCES quant_strategy(id),
    from_date      DATE         NOT NULL,
    to_date        DATE         NOT NULL,
    trade_date     DATE         NOT NULL,
    portfolio_value BIGINT      NOT NULL,           -- 원 단위
    return_pct     NUMERIC(10,6) NOT NULL,          -- 해당일 기준 누적 수익률 (0.0834 = 8.34%)
    cash           BIGINT       NOT NULL DEFAULT 0,
    equity         BIGINT       NOT NULL DEFAULT 0,
    created_at     TIMESTAMP    DEFAULT NOW(),
    CONSTRAINT uq_qbr UNIQUE (strategy_id, from_date, to_date, trade_date)
);

CREATE INDEX idx_qbr_strategy_date ON quant_backtest_result(strategy_id, from_date, to_date, trade_date);
백테스팅 실행 시 기존 (strategy_id, from_date, to_date) 조합 결과는 DELETE 후 재INSERT (캐시 무효화). 동일 기간 재조회 시 DB에서 즉시 반환 (재실행 없음).
4. quant_trade_log — 매매 이력
CREATE TABLE quant_trade_log (
    id             BIGSERIAL    PRIMARY KEY,
    strategy_id    BIGINT       NOT NULL REFERENCES quant_strategy(id),
    from_date      DATE         NOT NULL,           -- 백테스팅 시작일 (어느 run에 속하는지 식별)
    to_date        DATE         NOT NULL,
    trade_date     DATE         NOT NULL,
    asset_code     VARCHAR(20)  NOT NULL,
    asset_name     VARCHAR(100),
    asset_type     VARCHAR(10)  NOT NULL,
    trade_type     VARCHAR(10)  NOT NULL,           -- BUY | SELL
    price          NUMERIC(18,4) NOT NULL,
    quantity       BIGINT       NOT NULL,
    amount         BIGINT       NOT NULL,           -- price × quantity
    weight         NUMERIC(8,6),                   -- 포트폴리오 내 비중
    reason         VARCHAR(200),                   -- 매매 이유 텍스트
    commission     BIGINT       DEFAULT 0,
    tax            BIGINT       DEFAULT 0,
    created_at     TIMESTAMP    DEFAULT NOW()
);

CREATE INDEX idx_qtl_strategy ON quant_trade_log(strategy_id, from_date, to_date, trade_date);
