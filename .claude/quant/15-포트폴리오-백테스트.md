# 포트폴리오 백테스트

> 출처: 현율, *R을 이용한 퀀트 투자 포트폴리오 만들기(개정판)*, [Chapter 12 포트폴리오 백테스트](https://hyunyulhenry.github.io/quant_cookbook/%ED%8F%AC%ED%8A%B8%ED%8F%B4%EB%A6%AC%EC%98%A4-%EB%B0%B1%ED%85%8C%EC%8A%A4%ED%8A%B8.html)
> 정리일: 2026-05-20

## 1. 이 문서를 읽는 기준

이 장은 전략을 과거 데이터에 적용했을 때 수익률, 위험, 회전율, 비용 차감 후 성과가 어떻게 나오는지 검증하는 백테스트 과정을 다룬다.

현재 Market Pulse의 `MP_CORE`는 이미 백테스트 화면과 엔진이 있으므로, 이 문서는 대부분 `MP_CORE_NOW`에 해당한다.

| 분류 | 내용 | 판단 |
|---|---|---|
| `MP_CORE_NOW` | 리밸런싱 시점, 목표 비중, BOP/EOP, 회전율, 비용 차감, drawdown | 지금 엔진 신뢰성에 직결 |
| `MP_CORE_LATER` | 시점 선택 필터, 동적 자산배분형 방어 모드 | 모델 안정화 후 확장 |
| `NEXT_MODEL` | 60/40, 글로벌 동적자산배분, TAA | 별도 자산배분 전략 |
| `REFERENCE_ONLY` | R `Return.portfolio()` 사용법 | 구현 개념 참고 |

## 2. 글의 핵심

백테스트는 전략을 과거부터 실행했다고 가정했을 때의 성과를 보는 과정이다. 전략의 손익뿐 아니라 위험, 낙폭, 회전율, 비용 민감도, 어떤 구간에서 좋고 나빴는지를 파악할 수 있다.

다만 원문도 강조하듯이 백테스트는 이미 일어난 일을 대상으로 한다. 좋은 과거 수익률이 미래 반복을 보장하지 않는다.

Market Pulse 관점의 핵심:

- 백테스트는 단순 수익률 그래프가 아니라 전략 실행 로그여야 한다.
- 리밸런싱 날짜, 기준 데이터 날짜, 목표 비중, 체결 비중, 거래비용을 모두 재현 가능하게 저장해야 한다.
- 비용과 회전율을 빼지 않은 결과는 실제 성과보다 낙관적이다.
- look-ahead bias를 막기 위해 신호 계산 시점과 수익률 적용 시점을 분리해야 한다.
- 월별/주별 리밸런싱이 다르면 전략 성과와 회전율이 크게 달라진다.

## 3. Return.portfolio 개념

원문은 R의 `PerformanceAnalytics::Return.portfolio()`를 사용한다. 핵심 입력은 자산별 수익률과 리밸런싱 목표 비중이다.

주요 입력:

| 입력 | 의미 | MP_CORE 대응 |
|---|---|---|
| `R` | 자산별 수익률 시계열 | `market_daily_price`에서 계산한 daily return |
| `weights` | 리밸런싱 시점별 목표 비중 | `quant_portfolio_target` 후보 |
| `rebalance_on` | 리밸런싱 주기 | weekly/monthly/custom rebalance schedule |
| `value` | 초기 포트폴리오 가치 | `initialCash` |
| `verbose` | 상세 결과 반환 | trade log, equity curve, weights |

주요 출력:

| 출력 | 의미 | MP_CORE 대응 |
|---|---|---|
| returns | 포트폴리오 기간별 수익률 | equity curve |
| contribution | 자산별 성과기여도 | attribution |
| BOP.Weight | 기간 시작 비중 | 리밸런싱 전/후 검증 |
| EOP.Weight | 기간 종료 비중 | drift 확인 |
| BOP.Value | 기간 시작 평가액 | 거래 전 평가액 |
| EOP.Value | 기간 종료 평가액 | 거래 후/수익 반영 평가액 |

## 4. BOP/EOP 계산 흐름

원문은 포트폴리오 수익률이 아래 흐름으로 계산된다고 설명한다.

```text
전일 EOP.Value
-> 오늘 BOP.Value
-> 오늘 자산별 수익률 적용
-> 오늘 EOP.Value
-> 오늘 EOP.Weight
-> 리밸런싱일이면 다음 BOP.Weight를 target weight로 조정
```

리밸런싱이 없는 날:

```text
next BOP.Value = previous EOP.Value
```

리밸런싱이 있는 날:

```text
next BOP.Value = total portfolio value * target weight
```

### MP_CORE_NOW 적용

백테스트 엔진은 아래 값을 명확히 분리해야 한다.

```text
signalDate: 신호를 계산한 날짜
rebalanceDate: 목표 비중을 결정한 날짜
executionDate: 체결 가격을 적용한 날짜
returnStartDate: 수익률 적용 시작일
returnEndDate: 수익률 적용 종료일
```

중요:

- 당일 종가로 신호를 만들고 같은 종가로 체결하면 look-ahead 가능성이 있다.
- 안전하게는 `D일 종가 신호 -> D+1일 시가/종가 체결` 규칙이 필요하다.
- 현재 데이터가 종가만 있으면 체결 가정과 한계를 문서화해야 한다.

## 5. 회전율

원문은 리밸런싱 당일 시작 비중과 전일 종료 비중의 차이 절댓값 합으로 회전율을 계산한다.

계산:

```text
turnover_t = sum(abs(BOP.Weight_t - EOP.Weight_{t-1}))
```

예:

```text
전일 종료 비중: 주식 62.6%, 채권 37.4%
리밸런싱 후 시작 비중: 주식 60%, 채권 40%
turnover = abs(0.600 - 0.626) + abs(0.400 - 0.374) = 5.2%
```

### MP_CORE_NOW 적용

회전율은 비용 계산의 핵심이다.

필요 저장값:

```text
prevWeight
targetWeight
weightDiff
buyAmount
sellAmount
turnover
```

주의:

- 매수/매도 양쪽을 모두 더하면 전량 교체 시 200% 회전율이 된다.
- 비용 계산 시 매수 수수료, 매도 수수료, 매도세를 분리해야 한다.
- 정수 주식수 때문에 목표 비중과 실제 체결 비중이 달라진다.
- 회전율이 높은 전략은 세금과 슬리피지가 성과를 크게 깎는다.

## 6. 60/40 포트폴리오

원문은 주식 60%, 채권 40% 포트폴리오를 연간 리밸런싱으로 백테스트한다. 주식과 채권은 상관관계가 낮아 분산효과를 기대할 수 있고, 단일 주식 자산보다 안정적인 수익률을 보인다.

### MP_CORE 판단

60/40은 `MP_CORE` 직접 모델은 아니지만 좋은 벤치마크 개념이다.

활용:

- 전략이 단순 주식 매수 후 보유보다 나은지 비교한다.
- 위험 대비 성과를 시장/방어형 포트폴리오와 비교한다.
- 향후 자산배분 전략의 기본 모델로 보관한다.

다음 모델 후보:

```text
MP_60_40
- 주식 60%, 채권 40%
- 연간/분기/월간 리밸런싱 비교
- 국내형: KOSPI/KODEX 국채 ETF 후보
```

## 7. 시점 선택 전략

원문은 Meb Faber의 10개월 이동평균 기반 마켓 타이밍 전략을 설명한다.

규칙:

```text
price > 10-month moving average -> 주식 100%
price < 10-month moving average -> 현금 또는 단기채 100%
```

매월 말 기준으로 신호를 계산하고, 다음 기간의 비중을 결정한다. 이 전략은 상승장 전체를 완벽히 먹는 것보다 큰 하락장에서 낙폭을 줄이는 데 목적이 있다.

### MP_CORE_LATER 적용

이 내용은 `MP_CORE`의 방어 모드로 확장 가능하다.

피처/규칙 후보:

```text
index_price_above_ma_200
index_price_above_ma_10m
market_regime = RISK_ON | RISK_OFF
cash_weight_floor
max_stock_exposure
```

적용 예:

```text
KOSPI < 200일 이동평균이면:
- 신규 매수 점수 threshold 상향
- 현금 최소 비중 20~40%
- 고베타/고변동 종목 비중 축소
```

주의:

- 마켓 타이밍은 잦은 whipsaw가 생길 수 있다.
- 신호 기준일과 체결일을 분리해야 한다.
- 현금 수익률을 0으로 둘지, 단기채/예금 수익률로 둘지 정해야 한다.

## 8. 동적 자산배분

원문의 동적 자산배분 예시는 아래 규칙을 사용한다.

1. 글로벌 10개 자산 중 과거 12개월 수익률이 높은 5개 자산을 선택한다.
2. 선택된 5개 자산으로 최소분산 포트폴리오를 구성한다.
3. 각 자산 비중은 최소 10%, 최대 30%로 제한한다.
4. 매월 리밸런싱한다.

### MP_CORE 판단

동적 자산배분은 개별 종목 `MP_CORE`와는 별도 모델에 가깝다. 다만 구조는 참고할 만하다.

가져올 개념:

- lookback 기간으로 후보를 고른다.
- 후보군에만 비중을 부여한다.
- 비중 상한/하한을 둔다.
- 월별 리밸런싱한다.
- 회전율과 비용 차감 결과를 반드시 본다.

다음 모델 후보:

```text
MP_DAA
- 국내/글로벌 ETF universe
- 12개월 모멘텀 상위 K개 선택
- min-vol 또는 inverse-vol 비중
- 월간 리밸런싱
- 비용/세금 차감
```

## 9. 비용 차감

원문은 회전율이 높은 전략에서는 비용을 무시하면 안 된다고 설명한다.

순수익률 계산:

```text
net_return_t = gross_return_t - turnover_t * cost_rate
```

원문 예시는 총 비용 0.3%를 단순 가정한다. Market Pulse는 한국 주식 환경에 맞춰 비용을 더 세분화해야 한다.

현재 프로젝트 비용 구조 후보:

```text
buy_fee_rate = 0.00015
sell_fee_rate = 0.00015
sell_tax_rate = 0.0018
slippage_rate = optional
```

계산:

```text
buy_cost = buy_amount * buy_fee_rate
sell_cost = sell_amount * (sell_fee_rate + sell_tax_rate)
slippage_cost = traded_amount * slippage_rate
net_equity = gross_equity - buy_cost - sell_cost - slippage_cost
```

### MP_CORE_NOW 적용

백테스트 결과에는 최소한 아래를 같이 보여줘야 한다.

| 지표 | 의미 |
|---|---|
| grossReturn | 비용 차감 전 수익률 |
| netReturn | 비용 차감 후 수익률 |
| totalFee | 누적 수수료 |
| totalTax | 누적 매도세 |
| totalTurnover | 누적 회전율 |
| avgTurnover | 평균 리밸런싱 회전율 |
| tradeCount | 거래 횟수 |

## 10. MP_CORE 백테스트 체크리스트

### 데이터 시점

- 신호 계산에 미래 가격이 들어가지 않았는가?
- 재무 데이터는 발표일 이후부터만 사용했는가?
- 리밸런싱일의 가격 사용 가정이 명확한가?
- 신규상장/상장폐지/거래정지 종목을 어떻게 처리했는가?

### 포트폴리오

- 목표 비중 합이 1 또는 현금 포함 1인가?
- 종목별 최대 비중이 지켜지는가?
- 섹터별 최대 비중이 지켜지는가?
- 정수 주식수 반영 후 실제 비중을 다시 계산하는가?
- 현금 비중을 성과 계산에 포함하는가?

### 비용

- 매수 수수료와 매도 수수료를 모두 반영했는가?
- 매도세를 반영했는가?
- 회전율이 높을수록 성과가 낮아지는 구조인가?
- 매매가 없는 날 비용이 0인가?

### 출력

- equity curve가 비용 전/후로 분리되어 있는가?
- drawdown을 계산하는가?
- monthly/yearly return을 확인할 수 있는가?
- trade log로 결과를 재현할 수 있는가?
- 같은 요청이 같은 결과를 반환하는가?

## 14. 한 줄 요약

이 장의 핵심은 "전략의 수익률만 보지 말고, 리밸런싱 비중이 실제로 어떻게 변했고 회전율과 비용을 차감하면 무엇이 남는지까지 검증하라"는 것이다. `MP_CORE`에서는 백테스트를 거래 로그와 비용 차감 결과까지 재현 가능한 실행 시뮬레이션으로 만들어야 한다.
