## 1. 이 문서를 읽는 기준

이 장은 종목을 고른 뒤 각 종목 또는 자산에 얼마씩 투자할지 결정하는 포트폴리오 비중 산정 방법을 다룬다.

현재 Market Pulse의 중심은 `MP_CORE` 단일 코어 모델이므로, 복잡한 포트폴리오 최적화를 처음부터 전부 넣기보다는 아래 기준으로 분리한다.

| 분류 | 내용 | 판단 |
|---|---|---|
| `MP_CORE_NOW` | 점수 기반 비중, 최대 비중 제한, 섹터 제한, 현금 비중, 정수 주식수 계산 | 지금 바로 필요 |
| `MP_CORE_LATER` | 위험기여도, 공분산 기반 비중 조절, factor tilt | 모델 안정화 후 |
| `NEXT_MODEL` | 최소분산, 최대분산효과, 위험균형, 인덱스 인핸스드 | 별도 포트폴리오 엔진 |
| `REFERENCE_ONLY` | R 패키지별 최적화 구현 세부 문법 | 개념만 참고 |

## 2. 글의 핵심

원문은 포트폴리오 구성에서 비중 결정이 종목 선정만큼 중요하다고 설명한다.

핵심 주제:

- 최소분산 포트폴리오: 전체 포트폴리오 변동성이 가장 낮은 비중을 찾는다.
- 최대분산효과 포트폴리오: 낮은 상관관계를 활용해 분산효과를 최대화한다.
- 위험균형 포트폴리오: 각 자산의 위험기여도를 같게 만든다.
- 위험예산 포트폴리오: 자산군별 목표 위험기여도를 다르게 설정한다.
- 인덱스 포트폴리오: 시가총액비중으로 지수를 복제한다.
- 인핸스드 인덱스: 지수 비중을 기준으로 특정 팩터에 약간 더 노출되도록 비중을 틸트한다.

Market Pulse 관점의 핵심은 다음과 같다.

- `MP_CORE` 1차에서는 최적화보다 해석 가능하고 안정적인 비중 규칙이 우선이다.
- 종목별 최대 비중, 섹터별 최대 비중, 거래대금 기반 비중 제한은 즉시 필요하다.
- 공분산 최적화는 데이터 품질, 표본 기간, 계산 안정성 이슈가 있어 다음 단계로 둔다.
- 팩터 점수를 투자비중으로 바꿀 때는 제약조건과 재표준화가 필수다.

## 4. 공분산과 상관관계

원문은 글로벌 ETF 가격을 받아 수익률을 계산하고, 상관관계와 분산-공분산 행렬을 확인한다. 포트폴리오 최적화는 대부분 공분산 행렬을 기반으로 한다.

개념:

```text
correlation: 자산끼리 얼마나 같이 움직이는가
covariance matrix: 각 자산의 변동성과 자산 간 동행성을 함께 담은 행렬
portfolio variance = w' * covariance_matrix * w
```

### MP_CORE 적용

개별 주식 20~30개 포트폴리오에서도 상관관계는 중요하지만, 1차 구현에서는 최적화 입력보다 진단 지표로 쓰는 편이 안전하다.

진단 후보:

```text
average_pairwise_correlation
max_pairwise_correlation
sector_concentration
portfolio_volatility_estimate
portfolio_beta_estimate
```

주의:

- 최근 표본이 짧으면 공분산 추정이 불안정하다.
- 종목 수가 많고 기간이 짧으면 행렬이 특이하거나 최적화가 불안정해질 수 있다.
- 한국 주식은 시장 급락기에 상관관계가 동시에 높아질 수 있다.

## 5. 최소분산 포트폴리오

최소분산 포트폴리오는 포트폴리오 변동성을 최소화하는 비중을 찾는다.

목적:

```text
minimize 0.5 * w' * covariance_matrix * w
```

기본 제약:

```text
sum(weights) = 1
weight_i >= 0
```

원문은 `slsqp()`, `solve.QP()`, `optimalPortfolio()` 세 방법으로 같은 결과를 얻는다. 다만 단순 최소분산은 변동성이 낮은 일부 자산에 비중이 몰리는 구석해가 자주 발생한다.

### MP_CORE 판단

최소분산 최적화는 현재 `MP_CORE`의 첫 비중 방식으로는 과하다.

이유:

- 수익 기대값을 반영하지 않는다.
- 변동성이 낮은 종목에 과도하게 몰릴 수 있다.
- 공분산 추정 오차에 민감하다.
- 사용자가 이해하기 어려운 비중이 나올 수 있다.

`MP_CORE`에서는 최소분산 결과를 참고 진단 또는 다음 모델로 둔다.

다음 모델 후보:

```text
MP_MIN_VOL_PORTFOLIO
- 후보 종목 N개 선정
- 최근 252일 공분산 추정
- long-only
- 종목별 최대 10~15%
- 섹터별 최대 30%
- 월간 리밸런싱
```

## 6. 비중 상한/하한 제약

원문은 최소분산 결과가 특정 자산에 과도하게 몰리는 문제를 해결하기 위해 각 자산의 최소/최대 비중 제약을 추가한다.

예:

```text
sum(weights) = 1
lower_i <= weight_i <= upper_i
```

제약을 넣으면 더 현실적인 포트폴리오가 된다.

### MP_CORE_NOW 적용

비중 제약은 지금 바로 필요하다.

권장 기본값:

| 제약 | 기본값 후보 | 이유 |
|---|---:|---|
| 종목 최대 비중 | 10~18% | 단일 종목 리스크 제한 |
| 종목 최소 비중 | 0% 또는 2% | 너무 작은 포지션 방지 |
| 섹터 최대 비중 | 30~40% | 섹터 쏠림 완화 |
| KOSDAQ 최대 비중 | 40~60% | 시장 리스크 조절 |
| 현금 최소 비중 | 0~30% | 신호 약할 때 방어 |
| 종목 수 | 8~20개 | 과집중과 과분산 사이 |

현재 프로젝트에 이미 어울리는 방식:

```text
1. 후보 종목 score 계산
2. score가 약하면 현금 비중 유지
3. score 비례로 1차 비중 산정
4. 종목별 최대 비중 cap
5. 섹터별 최대 비중 cap
6. 남은 비중 재분배
7. 거래비용 고려 후 최종 주문 수량 계산
```

## 7. 최대분산효과 포트폴리오

최대분산효과 포트폴리오는 분산비율을 최대화하는 포트폴리오다.

분산비율:

```text
diversification_ratio = weighted_average_asset_volatility / portfolio_volatility
```

자산 간 상관관계가 낮을수록 포트폴리오 변동성이 더 크게 줄어들고, 분산비율은 커진다.

### MP_CORE 판단

개별 주식 포트폴리오에서는 참고할 수 있지만, 현재는 `NEXT_MODEL` 성격이 강하다.

활용 가능성:

- 후보 종목 간 상관이 너무 높은 경우 일부 제외
- 동일 섹터/동일 테마 종목의 중복 편입을 줄이는 진단
- 포트폴리오 구성 후 분산효과 점수 표시

다음 모델 후보:

```text
MP_MAX_DIVERSIFICATION
- 후보 자산의 변동성/상관관계 기반
- 분산비율 최대화
- 최소/최대 비중 제약
- 자산배분 또는 섹터 ETF 전략에 더 적합
```

## 8. 위험균형과 위험예산

위험균형 포트폴리오는 각 자산이 포트폴리오 전체 위험에 동일하게 기여하도록 비중을 정한다.

개념:

```text
risk_contribution_1 = risk_contribution_2 = ... = risk_contribution_n
```

위험예산 포트폴리오는 모든 자산의 위험기여도를 같게 하지 않고, 자산군별 목표 위험기여도를 다르게 설정한다.

예:

```text
주식 위험예산 60%
채권 위험예산 30%
금/대체자산 위험예산 10%
```

### MP_CORE 판단

위험균형은 단일 종목 예측 모델보다 자산배분 모델에 더 잘 맞는다. 다만 `MP_CORE` 포트폴리오 결과를 진단하는 데는 유용하다.

진단 후보:

```text
position_weight
asset_volatility
asset_beta
marginal_risk_contribution
risk_contribution_pct
```

활용:

- 특정 종목의 비중은 작아도 변동성이 커서 위험기여도가 큰지 확인한다.
- 포트폴리오의 실제 위험이 몇 종목에 몰렸는지 본다.
- 방어 모드에서는 위험기여도 상위 종목을 감액한다.

다음 모델 후보:

```text
MP_RISK_PARITY
- ETF/자산군 기반
- 위험기여도 균등
- 월간 리밸런싱

MP_RISK_BUDGET
- 주식/채권/금/현금 위험예산 지정
- 시장 국면별 위험예산 동적 변경
```

## 9. 인덱스 포트폴리오 복제

원문은 KOSPI 200을 시가총액 상위 200종목으로 단순 복제하고, 각 종목의 시가총액비중을 계산한다.

시가총액비중:

```text
market_cap_weight_i = market_cap_i / sum(market_cap_all)
```

실제 매수 수량:

```text
target_amount_i = total_cash * target_weight_i
shares_i = floor(target_amount_i / current_price_i)
```

정수 주식수로 내림 처리하면 남는 현금이 생긴다.

### MP_CORE_NOW 적용

정수 주식수 계산은 현재 백테스트/실거래 시뮬레이션에 바로 필요하다.

필요 로직:

```text
targetWeight -> targetAmount -> targetShares -> actualAmount -> residualCash
```

주의:

- 1주 단위 매수 때문에 목표 비중과 실제 비중이 달라진다.
- 고가주가 많으면 작은 시드에서는 추종 오차가 커진다.
- 리밸런싱 시 기존 보유 수량과 목표 수량의 차이만 거래해야 비용이 현실적이다.
- 거래정지/상한가/하한가 같은 체결 불가 상태를 반영해야 한다.

## 10. 인핸스드 인덱스와 팩터 틸트

원문은 KOSPI 200 시가총액비중을 기준으로 저PBR 종목에는 비중을 조금 더하고, 고PBR 종목에는 비중을 조금 빼는 인핸스드 인덱스 방식을 설명한다.

단순 틸트:

```text
저PBR 상위 그룹: benchmark_weight + 5bp
고PBR 하위 그룹: benchmark_weight - 5bp
재표준화
```

강한 틸트:

```text
factor_rank -> z_score -> normal_cdf -> benchmark_weight * cdf -> normalize
```

그 뒤 종목별 active weight 차이가 너무 커지지 않도록 제한한다.

```text
abs(target_weight - benchmark_weight) <= active_weight_cap
```

### MP_CORE_NOW / LATER 적용

이 장에서 `MP_CORE`에 가장 유용한 부분은 팩터 점수를 비중으로 바꾸는 방식이다.

현재 적용:

```text
score -> positive_score -> normalized_weight -> cap -> redistribute
```

나중 적용:

```text
benchmark_weight + factor_tilt
active_weight_cap
tracking_error budget
```

현재 `MP_CORE`는 벤치마크 추종보다 절대수익/모델 신호 기반에 가깝다. 따라서 인덱스 틸트 자체보다는 "점수를 비중으로 변환하고 제약을 거는 방법"만 우선 가져온다.

## 11. MP_CORE 비중 산정 제안

1차 권장 방식:

```text
input:
- candidate stocks
- model score
- risk score
- liquidity score
- sector
- price
- cash

step:
1. score <= threshold 종목 제외
2. score를 0 이상 값으로 변환
3. score 합으로 기본 비중 계산
4. 변동성/유동성으로 비중 조정
5. 종목별 maxWeight 적용
6. 섹터별 maxSectorWeight 적용
7. 신호 평균이 낮으면 현금 비중 유지
8. target shares 계산
9. 거래비용과 세금 반영
```

수식 예시:

```text
raw_weight_i = max(score_i, 0) / sum(max(score, 0))
risk_adjusted_weight_i = raw_weight_i / volatility_i
liquidity_adjusted_weight_i = min(risk_adjusted_weight_i, liquidity_cap_i)
final_weight = normalize_after_caps(liquidity_adjusted_weight)
```

제약 후보:

```text
max_stock_weight = 0.18
max_sector_weight = 0.35
max_kosdaq_weight = 0.50
min_cash_weight = dynamic, 0.00 ~ 0.30
max_turnover_per_rebalance = 0.50
```

## 12. DB/API 설계 후보

포트폴리오 목표 비중과 실제 체결 수량을 분리해서 저장하면 백테스트 재현성이 좋아진다.

```sql
CREATE TABLE quant_portfolio_target (
    id BIGSERIAL PRIMARY KEY,
    run_id BIGINT,
    rebalance_date DATE NOT NULL,
    asset_code VARCHAR(20) NOT NULL,
    target_weight NUMERIC(18, 8) NOT NULL,
    target_amount NUMERIC(20, 4),
    target_shares NUMERIC(20, 4),
    model_score NUMERIC(18, 8),
    risk_adjustment NUMERIC(18, 8),
    sector VARCHAR(100),
    created_at TIMESTAMP DEFAULT NOW()
);
```

진단 API 후보:

```text
GET /api/quant/portfolio/target?runId=
GET /api/quant/portfolio/exposure?runId=
GET /api/quant/portfolio/risk-contribution?runId=
GET /api/quant/portfolio/rebalance-diff?runId=
```

프론트 차트 후보:

- 목표 비중 bar chart
- 섹터 비중 pie/bar chart
- 현금 비중
- 목표 비중 vs 실제 비중 차이
- 리밸런싱 매수/매도 금액

## 13. 헷갈리지 않기 위한 저장 방식

이번 장 기준 분류:

| 분류 | 항목 |
|---|---|
| `MP_CORE_NOW` | 점수 기반 비중, 종목/섹터 max cap, 현금 비중, 정수 주식수 |
| `MP_CORE_LATER` | 위험기여도, active weight, factor tilt |
| `NEXT_MODEL` | 최소분산, 최대분산효과, 위험균형, 위험예산, 인덱스 복제 |
| `REFERENCE_ONLY` | `slsqp`, `solve.QP`, `optimalPortfolio`, `rp` 세부 구현 |

## 14. 한 줄 요약

이 장의 핵심은 "좋은 종목을 고른 뒤에도 비중 제약과 위험 관리가 없으면 포트폴리오가 쉽게 망가진다"는 것이다. `MP_CORE`에는 복잡한 최적화보다 점수 기반 비중, 종목/섹터 상한, 현금 비중, 정수 주식수 계산을 먼저 넣고, 최소분산·위험균형·인덱스 틸트는 다음 포트폴리오 엔진 후보로 보관하는 것이 맞다.
