## 1. 글의 핵심

이 장은 수집과 정리가 끝난 데이터를 대상으로 탐색적 데이터 분석(EDA)을 수행하고, 데이터의 분포·관계·극단치·결측을 시각적으로 확인하는 방법을 다룬다.

Market Pulse의 `MP_CORE` 관점에서 핵심은 다음과 같다.

- 모델을 만들기 전에 데이터 구조, 타입, 결측, 극단치, 섹터 분포를 먼저 봐야 한다.
- `join`, `filter`, `mutate`, `group_by`, `summarize`, `rank`, `ntile`은 퀀트 팩터 생성의 기본 연산이다.
- 산점도, 히스토그램, 박스플롯, 막대그래프는 팩터 품질과 universe 편향을 확인하는 가장 빠른 도구다.
- 주가/수익률 차트와 연도별 수익률 시각화는 백테스트 결과를 검증하는 기본 화면이다.
- R의 `dplyr`/`ggplot2` 개념은 현재 프로젝트의 PostgreSQL/MyBatis/React/Recharts 구조로 옮겨 구현할 수 있다.

## 3. 종목정보 결합과 구조 확인

원문은 거래소 종목정보(`KOR_ticker`)와 WICS 섹터정보(`KOR_sector`)를 읽고 종목코드를 6자리로 맞춘 뒤 `left_join()`으로 결합한다.

핵심 개념:

- 종목코드는 반드시 문자열 6자리로 관리한다.
- 종목 마스터와 섹터 데이터는 종목코드/종목명 기준으로 결합한다.
- `left_join()`은 기준 universe를 유지하면서 부가 정보를 붙이는 방식이다.
- 결합 후 `glimpse()`로 행 수, 열 수, 타입, 일부 값을 확인한다.

### MP_CORE 적용

Market Pulse에서는 아래 조합이 종목 분석의 기본 입력이 된다.

```text
stock_master
+ market_daily_price latest row
+ sector mapping
+ value/quality feature
+ liquidity feature
+ ranking snapshot
```

기본 검증 쿼리 후보:

```sql
SELECT
    COUNT(*) AS row_count,
    COUNT(DISTINCT asset_code) AS asset_count,
    COUNT(*) FILTER (WHERE sector IS NULL) AS missing_sector_count,
    COUNT(*) FILTER (WHERE close_price IS NULL OR close_price <= 0) AS invalid_price_count
FROM market_daily_price
WHERE asset_type = 'STOCK'
  AND trade_date = :baseDate;
```

데이터 결합 규칙:

- universe 기준 테이블은 명확히 하나로 정한다.
- 가격은 기준일을 명시해서 붙인다.
- 섹터 누락 종목은 분석 화면에서 별도 그룹으로 표시한다.
- 동일 종목명이 있어도 종목코드를 primary key로 쓴다.

## 5. 팩터 생성 예시

원문은 PBR과 PER을 숫자형으로 바꾼 뒤 `ROE = PBR / PER`로 근사 ROE를 만들고, 시가총액 중앙값 기준으로 `big`/`small` 그룹을 만든다.

`MP_CORE`에서는 같은 아이디어를 아래처럼 feature로 만든다.

```text
roe_proxy = pbr / per
size_bucket = market_cap >= median(market_cap) ? BIG : SMALL
value_score = rank_low(pbr) + rank_low(per)
quality_score = rank_high(roe_proxy)
```

주의:

- `ROE = PBR / PER`은 재무제표 기반 ROE의 대체값이다. 정확한 ROE는 순이익/자본으로 계산해야 한다.
- PER이 0, 음수, 결측이면 ROE proxy도 왜곡된다.
- 시가총액 중앙값 기준 big/small은 간단하지만, 실전 universe에서는 거래대금과 시총 분위수를 함께 본다.

SQL 예시:

```sql
WITH base AS (
    SELECT
        asset_code,
        asset_name,
        sector,
        market_cap,
        per,
        pbr,
        CASE
            WHEN per > 0 AND pbr > 0 THEN pbr / per
            ELSE NULL
        END AS roe_proxy
    FROM quant_feature_snapshot
    WHERE base_date = :baseDate
),
ranked AS (
    SELECT
        *,
        NTILE(5) OVER (ORDER BY pbr ASC NULLS LAST) AS pbr_tile,
        ROW_NUMBER() OVER (ORDER BY roe_proxy DESC NULLS LAST) AS roe_rank
    FROM base
)
SELECT *
FROM ranked;
```

## 6. 필터와 스크리닝

원문은 PBR 1 미만 종목, PBR 1 미만 + PER 20 미만 + ROE 0.1 초과 종목처럼 조건을 조합해 후보군을 찾는다.

`MP_CORE`에서는 이 개념을 스크리닝 또는 universe filter로 사용한다.

기본 스크리닝 후보:

| 조건 | 의미 | 주의 |
|---|---|---|
| `PBR < 1` | 장부가 대비 저평가 | 금융/유틸리티 편중 가능 |
| `PER < 20` | 이익 대비 과도한 고평가 제외 | 적자 기업 음수 PER 처리 필요 |
| `ROE > 0.1` | 수익성 필터 | 일회성 이익 확인 필요 |
| `market_cap_rank <= N` | 유동성 확보 | 소형주 알파 일부 포기 |
| `trade_amount >= threshold` | 체결 가능성 | 시장 상황별 threshold 조정 |

중요한 점은 필터가 많아질수록 과최적화 위험이 커진다는 것이다. 필터는 모델 성과를 높이기 위한 장치가 아니라, 체결 불가·데이터 불량·극단 리스크를 제거하는 장치로 먼저 써야 한다.

## 7. 순위와 분위수

원문은 `row_number()`로 PBR 낮은 순위, ROE 높은 순위를 계산하고 `ntile()`로 PBR 5분위 그룹을 만든다.

퀀트 모델에서 순위와 분위수는 매우 중요하다.

활용:

- Value: PER/PBR/PCR/PSR 낮은 순위
- Quality: ROE/ROA/FCF margin 높은 순위
- Momentum: 최근 수익률 높은 순위
- Low volatility: 변동성 낮은 순위
- Liquidity: 거래대금 높은 순위

분위수 사용 방식:

| 분위수 | 활용 |
|---|---|
| 5분위 | 대략적 그룹 비교 |
| 10분위 | factor decile 성과 분석 |
| 100분위 | percentile score |

백테스트에서는 각 분위수별 미래 수익률을 비교해 팩터의 방향성이 맞는지 확인한다.

```text
예: PBR 1분위가 PBR 5분위보다 지속적으로 수익률이 높은가?
예: 모멘텀 상위 10%가 하위 10%보다 비용 차감 후에도 우수한가?
```

## 8. 그룹별 요약

원문은 `group_by(SEC_NM_KOR)` 후 섹터별 종목 수와 PBR 중앙값을 구한다. 이어서 시장구분과 섹터를 함께 묶어 KOSPI/KOSDAQ별 섹터 valuation 차이를 본다.

Market Pulse에서 필요한 그룹 분석:

| 그룹 | 확인할 것 |
|---|---|
| 시장별 | KOSPI/KOSDAQ 수익률, 변동성, valuation 차이 |
| 섹터별 | 종목 수, PBR/PER 중앙값, 거래대금, 모멘텀 |
| 시총 그룹별 | 대형/중형/소형 성과 차이 |
| 유동성 그룹별 | 거래대금에 따른 슬리피지 위험 |
| 팩터 분위별 | factor monotonicity |

섹터별 PBR 중앙값 쿼리 예시:

```sql
SELECT
    sector,
    percentile_cont(0.5) WITHIN GROUP (ORDER BY pbr) AS pbr_median,
    COUNT(*) AS stock_count
FROM quant_feature_snapshot
WHERE base_date = :baseDate
  AND pbr IS NOT NULL
GROUP BY sector
ORDER BY pbr_median;
```

## 10. 종목정보 시각화

원문은 ROE와 PBR 산점도를 그리고, 극단치 때문에 관계가 잘 보이지 않으면 `coord_cartesian()`으로 축 범위를 제한한다. 이후 시장구분별 색상/모양을 다르게 하고 회귀선을 추가한다.

Market Pulse에서 필요한 팩터 진단 차트:

| 차트 | 목적 |
|---|---|
| ROE x PBR 산점도 | Quality와 valuation 관계 확인 |
| PER/PBR 히스토그램 | 극단치와 분포 확인 |
| 섹터별 PBR 박스플롯 | 업종별 valuation 차이 확인 |
| 섹터별 ROE/PBR 중앙값 산점도 | 섹터 단위 포지셔닝 |
| 섹터별 종목 수 막대그래프 | universe 편중 확인 |
| 팩터 분위별 미래수익률 막대그래프 | 팩터 유효성 확인 |

### 극단치 처리

시각화에서 축을 자르는 것은 데이터를 삭제하는 것과 다르다. 원문처럼 `coord_cartesian()`은 화면 표시 범위만 제한한다.

`MP_CORE`에서도 아래를 구분한다.

- 분석용 raw value: 원본 유지
- 시각화용 clipped value: 차트 가독성 목적
- 모델용 winsorized value: 학습 안정성 목적

권장 필드:

```text
pbr_raw
pbr_winsorized
pbr_display
```

## 12. 주가 및 수익률 시각화

원문은 `quantmod`로 SPY 가격을 받고, 기본 `plot`, `ggplot`, `dygraphs`, `highcharter`, `plotly`로 가격선을 그린다. 마지막으로 `PerformanceAnalytics`로 연도별 누적 수익률을 계산해 막대그래프로 표시한다.

Market Pulse 기존 `/quant` 화면과 직접 연결되는 부분이다.

필요 차트:

| 차트 | 현재/후보 컴포넌트 | 목적 |
|---|---|---|
| equity curve | `EquityChart` | 전략 누적 수익률 |
| drawdown | `DrawdownChart` | 낙폭과 회복 기간 |
| monthly/yearly return | `MonthlyReturnHeatmap` 또는 bar chart | 수익률 계절성/일관성 |
| allocation | `AllocationChart` | 리밸런싱 후 자산 비중 |
| trade timeline | `TradeTimeline` | 매수/매도 이벤트 검증 |
| factor scatter | 신규 후보 | 팩터 관계 확인 |

연도별 수익률 계산 개념:

```text
daily_return = equity[t] / equity[t-1] - 1
yearly_return = product(1 + daily_return in year) - 1
```

주의:

- 단순 평균 수익률이 아니라 누적 곱으로 계산한다.
- 연도 첫날/마지막날 데이터 누락을 확인한다.
- 배당/수수료/세금 반영 여부를 chart subtitle이나 tooltip에 표시한다.

## 15. 구현 시 주의사항

- 차트가 예쁘다고 모델이 좋은 것은 아니다. 시각화는 먼저 데이터 오류를 찾기 위한 도구다.
- 극단치를 숨기면 안 된다. raw 분포와 clipped 분포를 함께 볼 수 있어야 한다.
- 섹터별 차이는 팩터 성과로 오해하기 쉽다. 섹터 중립 rank를 병행한다.
- 백테스트 수익률 차트는 비용 차감 전/후를 명확히 구분한다.
- 차트용 aggregation이 백테스트 계산 로직과 다르면 결과가 서로 달라 보일 수 있다.
- 프론트에서 임의로 중요한 계산을 다시 하지 말고, 재현 가능한 핵심 계산은 백엔드에서 수행한다.
