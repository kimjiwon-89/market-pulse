# 퀀트투자 분석(1): 퀀트와 전체 프로세스

> 출처: EO, 네이버 블로그, [[금융공학] 퀀트투자 분석(1) - 퀀트와 전체 프로세스](https://blog.naver.com/aza425/223654937451)
> 정리일: 2026-05-20

## 1. 글의 핵심

이 글은 퀀트투자를 처음 공부하는 관점에서 필요한 기초 역량, 퀀트투자의 장단점, 주요 투자 유형, 그리고 실제 모델 개발 프로세스를 한 번에 정리한 입문형 자료다.

Market Pulse의 `MP_CORE` 모델 설계 관점에서는 아래 3가지가 특히 중요하다.

- 퀀트 모델은 직관이나 뉴스 감정이 아니라 데이터, 수학, 통계, 알고리즘으로 의사결정해야 한다.
- 백테스트는 필수지만 과거 데이터 의존과 데이터마이닝 위험을 항상 경계해야 한다.
- 모델은 `데이터베이스 구축 → 팩터 개발 → 모델 개발 → 주식 scoring → 포트폴리오 최적화 → 백테스트 → 트레이드 리스트` 순서로 만들어야 한다.

## 2. 퀀트를 배우는 데 필요한 역량

| 영역 | 내용 | Market Pulse 반영 |
|---|---|---|
| 수학 | 선형대수, 미적분, 확률, 통계 | 회귀, 분류, 포트폴리오 최적화, 성과 검정 |
| 프로그래밍 | Python, R, 데이터 분석 도구 | Python/scikit-learn 학습 스크립트와 Spring API 분리 |
| 금융 지식 | 시장 구조, 자산배분, 파생상품 이해 | 투자 universe, 거래비용, 리밸런싱, 리스크 관리 |
| 데이터 분석 | 머신러닝, 데이터마이닝, 빅데이터 처리 | Random Forest, factor scoring, walk-forward 검증 |

## 3. 퀀트투자의 정의와 특징

퀀트는 금융/투자 영역에서 수학적 모델, 통계, 컴퓨터 알고리즘을 이용해 데이터 기반 의사결정을 내리는 방법이다.

핵심 목적:

- 투자 전략 개발
- 시장 데이터 분석
- 리스크 관리
- 거래비용을 감안한 위험조정 기대수익률 최대화

Market Pulse 관점에서는 단순히 “오를 종목 찾기”가 아니라, 비용과 리스크를 반영해 반복 가능한 매수/매도 의사결정 체계를 만드는 것이 핵심이다.

## 4. 장점과 한계

### 장점

- 많은 종목에 동시에 적용할 수 있어 분산투자에 유리하다.
- 규칙이 명확하면 전 세계 또는 대규모 universe에 반복 적용할 수 있다.
- 인간의 직관, 감정, 행동편향을 줄일 수 있다.
- 과거 데이터로 거래 규칙을 백테스트할 수 있다.
- 투자 판단을 데이터와 과학적 방법 중심으로 전환한다.

### 한계

- 정성 정보, 전화통화, 현장감 같은 soft information을 직접 반영하기 어렵다.
- 과거 데이터 의존성이 높고 데이터마이닝 위험이 있다.
- 학습하지 않은 새로운 이벤트에는 대응력이 낮을 수 있다.

### MP_CORE 설계 반영

- soft information 한계는 1차 MVP에서 인정하고, 뉴스/공시/컨퍼런스콜 텍스트 분석은 2차로 미룬다.
- 데이터마이닝 위험은 walk-forward 검증, out-of-sample 테스트, 거래비용 차감 성과로 통제한다.
- 새로운 이벤트 위험은 시장 국면 필터, 손절, 현금 비중 확대 규칙으로 완화한다.

## 5. 퀀트투자의 종류

| 유형 | 설명 | 개인/Market Pulse 적합성 |
|---|---|---|
| Fundamental Quant | 기업의 가치, 품질, 모멘텀, 사이즈, 저위험 등을 정량화해 투자 | 적합. `MP_CORE`의 장기 확장 방향 |
| 통계적 차익거래 | 가격 간 통계적 관계나 괴리를 이용 | 일부 가능. 페어트레이딩/스프레드 데이터 필요 |
| 고빈도 매매 | 밀리초/마이크로초 단위 초단기 매매 | 부적합. 인프라, 체결 속도, 수수료 구조가 개인 서비스와 맞지 않음 |

이 글의 분류를 기준으로 보면, Market Pulse는 고빈도 매매보다 `Fundamental Quant + 머신러닝 scoring + 포트폴리오 백테스트` 노선이 맞다.

## 6. 퀀트 프로세스

글에서 제시한 전체 프로세스는 다음 순서다.

```text
데이터베이스 구축
→ 퀀트 팩터 개발
→ 퀀트 모델 개발
→ 주식 Scoring
→ 포트폴리오 최적화
→ 포트폴리오 백테스트
→ 트레이드 리스트 생성
```

### Market Pulse 적용안

| 단계 | 구현 내용 |
|---|---|
| 데이터베이스 구축 | `market_daily_price`, `stock_master`, investor 수급 데이터 정비 |
| 팩터 개발 | Value, Momentum, Quality, Low Volatility, Behavioral Signal 후보 정의 |
| 모델 개발 | Random Forest로 비선형 관계 학습, 회귀/로짓은 baseline 또는 검증용 |
| 주식 Scoring | `P(WINNER)`, factor score, liquidity score, risk score를 합성 |
| 포트폴리오 최적화 | 초기에는 변동성 역가중 + 종목별 최대 비중, 이후 HRP 검토 |
| 백테스트 | 비용, 세금, 손절/익절, 리밸런싱, 현금 비중 포함 |
| 트레이드 리스트 | 실제 매수/매도 후보, 목표 비중, 매매 사유 출력 |

## 7. 데이터베이스 구축

글에서는 국가별 데이터 소스로 아래를 언급한다.

| 시장 | 언급된 데이터 소스 | Market Pulse 판단 |
|---|---|---|
| 미국 | Quandl/Nasdaq, Fama-French, TA-Lib | 해외 확장 시 참고 |
| 일본 | Stooq, TA-Lib | 현재 범위 밖 |
| 한국 | FinanceDataReader, FnGuide | 한국 주식 모델에 직접 관련 |

### 현재 프로젝트와의 연결

Market Pulse는 이미 KRX/KIS 기반 구조가 있으므로, 한국 데이터는 아래 우선순위가 적절하다.

1. KRX/KIS 무료 데이터로 가격, 거래량, 거래대금, 시가총액, 지수 데이터 확보
2. 종목별 외국인/기관 수급 데이터 확장
3. 재무 데이터가 필요해지면 DART 가공 또는 FnGuide/FnSpace 유료 API 검토
4. 기술적 지표는 TA-Lib 없이도 Java/Python에서 직접 계산 가능

## 8. 퀀트 팩터 개발

### 8.1 Value

정의: 기업 가치 대비 주가가 싼지를 보는 팩터.

주요 지표:

- PER
- PBR
- EV/EBITDA

Market Pulse 적용:

- MVP에서는 재무 데이터가 부족하므로 제외하거나 placeholder로 둔다.
- 재무 데이터 확보 후 `value_score`로 추가한다.
- 포트폴리오 PER/PBR 집계는 `.claude/quant/05-포트폴리오-밸류에이션.md` 기준으로 가중 조화평균을 사용한다.

### 8.2 Momentum

정의: 과거 수익률이 좋은 종목이 이후에도 강할 수 있다는 가설.

주요 지표:

- 12-1개월 모멘텀
- RSI
- 최근 6개월 수익률

Market Pulse 적용:

- MVP 핵심 피처로 바로 사용 가능하다.
- `ret_5d`, `ret_20d`, `ret_60d`, `ret_120d`, `ret_252d_ex_20d`, `rsi_14d`로 확장한다.
- 단기 모델에서는 20영업일 예측, 중기 확장에서는 6~12개월 모멘텀을 활용한다.

### 8.3 Quality

정의: 재무 상태와 경영 품질이 높은 기업을 선호하는 팩터.

주요 지표:

- Accrual
- ROE
- Debt-to-Equity Ratio
- Earnings Stability

Market Pulse 적용:

- 현재 무료 가격 데이터만으로는 정식 구현이 어렵다.
- DART 또는 유료 재무 API가 붙으면 `quality_score`로 추가한다.
- 단기 `MP_CORE`에서는 재무 품질보다 가격/수급/변동성을 우선한다.

### 8.4 Low Volatility

정의: 낮은 변동성 대비 좋은 성과를 추구하는 팩터.

주요 지표:

- Historical Volatility
- Beta
- Maximum Drawdown

Market Pulse 적용:

- MVP에서 즉시 구현 가능하다.
- `vol_20d`, `vol_60d`, `beta_120d`, `drawdown_60d`, `mdd_120d`로 피처화한다.
- 포트폴리오 비중 산정에서 변동성 역가중 또는 리스크 제한에 사용한다.

### 8.5 Behavioral Economic Signals

정의: 투자자의 심리와 행동 편향에서 발생하는 신호.

주요 요소:

- 뉴스/소셜/검색 트렌드 감성
- 과매수/과매도
- 투자자 흐름

Market Pulse 적용:

- MVP에서는 뉴스/소셜 감성은 제외한다.
- 현재 프로젝트의 외국인/기관 수급 데이터는 행동/수급 신호의 현실적 대체재로 쓸 수 있다.
- 향후 뉴스 NLP, 공시 NLP, 검색량 데이터가 붙으면 별도 `behavior_score`로 확장한다.

## 9. 퀀트 모델 개발

글에서 언급한 모델 개발 방향:

- 머신러닝으로 비선형성 포착
- Fama-French 모델과 Fama-MacBeth 회귀로 팩터 프리미엄 검증
- Zipline/Alphalens로 factor model 사전 검증

### Market Pulse 적용

| 방법 | 용도 | 우선순위 |
|---|---|---|
| Random Forest | 여러 피처의 비선형 조합으로 `WINNER/NEUTRAL/LOSER` 분류 | 1차 |
| 선형 회귀/로짓 | baseline, factor 방향성 검증, 설명력 확인 | 1차 보조 |
| Fama-MacBeth | factor premium 검증 | 2차 |
| Alphalens 유사 분석 | factor IC, quantile return 분석 | 2차 |
| Boosting Tree | Random Forest 이후 성능 비교 | 2차 |

## 10. 주식 Scoring

글에서는 factor score를 고려해 예상 수익률을 산출하는 scoring을 제안한다.

Market Pulse의 scoring은 아래처럼 잡는다.

```text
core_score
= winner_prob_score
+ momentum_score
+ liquidity_score
+ investor_flow_score
- volatility_penalty
- drawdown_risk_penalty
```

MVP에서는 점수 자체를 수익률로 단정하지 않는다. 점수는 종목 랭킹과 목표 비중 산정에 쓰고, 실제 기대수익률은 백테스트와 live 검증으로 분리한다.

## 11. 포트폴리오 최적화

글에서는 HRP(Hierarchical Risk Parity)를 언급한다.

HRP의 핵심:

- 자산 간 상관관계를 이용해 유사한 자산을 묶는다.
- 평균-분산 최적화보다 추정 오류에 덜 민감한 방식으로 리스크를 배분한다.
- 리스크 균형을 중시한다.

Market Pulse 적용:

- 1차 MVP: 단순하고 검증 쉬운 `동일비중 + 종목별 최대비중 + 변동성 역가중` 사용
- 2차: HRP를 포트폴리오 엔진 후보로 추가
- 3차: sector/market clustering을 반영한 과집중 방지

## 12. 포트폴리오 백테스트

글에서는 Zipline/Pyfolio 기반 이벤트 백테스팅과 성과 분석을 언급한다.

Market Pulse 적용:

- Java 백엔드의 기존 백테스트 구조를 유지하되, Core 모델은 이벤트 기반에 가깝게 보강한다.
- 신호일과 체결일을 분리해 look-ahead bias를 막는다.
- 수수료, 세금, 리밸런싱 비용, 미체결 가능성을 반영한다.
- Pyfolio의 사고방식처럼 수익률뿐 아니라 MDD, Sharpe, drawdown, 월별 성과, 회전율을 같이 본다.

## 13. 트레이드 리스트 생성

마지막 결과물은 실제 매매에 쓸 수 있는 리스트다.

Market Pulse에서 필요한 트레이드 리스트 필드:

| 필드 | 설명 |
|---|---|
| signal_date | 신호 생성일 |
| execution_date | 체결 가정일 |
| asset_code | 종목코드 |
| asset_name | 종목명 |
| action | BUY, SELL, HOLD |
| winner_prob | 상승 확률 |
| score | 종합 점수 |
| target_weight | 목표 비중 |
| current_weight | 현재 비중 |
| reason | 매매 사유 |
| risk_flags | 변동성, 유동성, 시장 국면 경고 |

## 14. MP_CORE에 반영할 결론

이 글을 기준으로 보면 `MP_CORE`는 다음 구조가 가장 자연스럽다.

1. `Fundamental Quant` 방향을 최종 목표로 삼되, MVP는 가격/수급/변동성 중심으로 시작한다.
2. `Momentum`, `Low Volatility`, `Behavioral Flow`는 현재 데이터로 바로 시작 가능한 핵심 팩터다.
3. `Value`, `Quality`는 재무 데이터 확보 후 붙인다.
4. 모델은 Random Forest로 비선형성을 먼저 포착하고, 회귀/로짓은 보조 검증 도구로 둔다.
5. 포트폴리오 최적화는 MVP에서 단순 리스크 제한으로 시작하고, HRP는 2차 후보로 둔다.
6. 백테스트는 수익률만 보지 않고 거래비용, MDD, Sharpe, 월별 성과, 회전율을 함께 평가한다.
7. 최종 사용자 산출물은 "종목 추천"이 아니라 매매 사유와 리스크가 포함된 트레이드 리스트여야 한다.

## 15. 현재 프로젝트에 추가로 필요한 것

| 필요 항목 | 이유 | 우선순위 |
|---|---|---|
| 종목별 전체 일별 수급 데이터 | Behavioral/flow signal 구현 | 높음 |
| feature snapshot 테이블 | 학습 시점과 신호 시점의 데이터 재현성 확보 | 높음 |
| model version 테이블 | 어떤 모델이 어떤 데이터로 학습됐는지 추적 | 높음 |
| signal/trade list 테이블 | 신호와 실제 매매 후보를 분리 저장 | 높음 |
| 재무 데이터 파이프라인 | Value/Quality factor 구현 | 중간 |
| HRP 포트폴리오 엔진 | 고도화된 리스크 배분 | 중간 |
| 뉴스/공시 NLP | soft information 보완 | 낮음 |
