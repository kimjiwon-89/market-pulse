## 플랫폼 정체성

**"통계로 세상을 읽는 분석 플랫폼"**

단순 데이터 조회가 아니라, 공개된 데이터에 통계 모델을 입혀서
인사이트와 실험의 재미를 동시에 제공하는 것이 핵심 가치.

모든 콘텐츠는 아래 패턴을 따른다:

```
실제 공개 데이터 수집
    ↓
통계 모델 적용 (팩터 분석 · 빈도 분석 · 시뮬레이션 등)
    ↓
결과 시각화 + 사용자 실험 가능
    ↓
누적 성적 추적 → 모델 성능 검증
```

퀀트 트레이드(Quantitative Trading)에서 시작해서,
**통계 기반이라면 주식 외 어떤 도메인으로도 확장 가능**.

## 통계 기반 콘텐츠 확장 방향

플랫폼 정체성에 맞는 확장 후보들. 모두 **공개 데이터 + 통계 모델** 패턴.

### 금융 도메인 확장

| 아이디어 | 데이터 소스 | 핵심 통계 |
|----------|------------|-----------|
| **암호화폐 퀀트** | 업비트·바이낸스 공개 API | 주식 퀀트 모델 그대로 적용 가능 |
| **환율 패턴 분석** | 한국은행 OpenAPI | 시계열 통계, 계절성 분석 |
| **ETF 팩터 분석** | KRX ETF API | 팩터 노출도, 상관관계 분석 |
| **옵션 전략 시뮬레이터** | KIS 파생 API | Greeks 계산, 손익 시뮬레이션 |

### 비금융 도메인 확장

| 아이디어 | 데이터 소스 | 핵심 통계 |
|----------|------------|-----------|
| **부동산 통계** | 국토교통부 실거래가 공개 API | 지역별 가격 추이, 회귀 분석 |
| **경제 지표 대시보드** | 한국은행·통계청 OpenAPI | GDP·CPI·금리 상관관계 |
| **스포츠 통계** | 공개 기록 데이터 | 확률 모델, 성과 예측 |

### 공통 확장 패턴

새 콘텐츠를 추가할 때 아래 3가지가 갖춰지면 플랫폼 정체성에 맞음:
1. **공개 데이터** — 직접 수집 가능한 소스 존재
2. **통계 모델** — 단순 조회가 아닌 분석·시뮬레이션 레이어
3. **누적 추적** — 모델 성능을 시간 흐름에 따라 검증 가능

## 기술 스택 확장 고려

현재 인프라(Spring Boot + PostgreSQL + React)가 통계 콘텐츠 확장에 충분.  
데이터가 늘어나면 추가 고려:

- **데이터 파이프라인**: 배치 수집 스케줄러 (현재 Spring @Scheduled로 커버)
- **재무 데이터**: DART OpenAPI (무료) — 매직포뮬러·GP/A 모델 구현 필요 시
- **시계열 저장**: TimescaleDB 또는 PostgreSQL 파티셔닝 (데이터 급증 시)
