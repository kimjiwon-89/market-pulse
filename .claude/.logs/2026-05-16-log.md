### 로또 실데이터 수집 인프라 구축 + 1223회차 전체 DB 입력

**배경**  
기존 DB에 테스트용 가짜 데이터(균등 분포 번호)가 들어 있어 분석 결과가 무의미한 상태.  
동행복권 `/common.do` API가 1000건 이상 요청 시 IP 레벨 차단 + 사이트 리뉴얼 후 API 엔드포인트 자체 폐쇄.

**해결**  
동행복권 대신 smok95 GitHub Pages(`smok95.github.io/lotto/results/all.json`) 공개 데이터셋 활용.  
터미널에서 `curl | jq | curl` 파이프라인으로 포맷 변환 후 백엔드에 일괄 전송.

```bash
curl -s "https://smok95.github.io/lotto/results/all.json" \
  | jq '[.[] | {drwNo: .draw_no, drwNoDate: (.date | split("T")[0]), drwtNo1: .numbers[0], drwtNo2: .numbers[1], drwtNo3: .numbers[2], drwtNo4: .numbers[3], drwtNo5: .numbers[4], drwtNo6: .numbers[5], bnusNo: .bonus_no}]' \
  | curl -s -X POST http://localhost:8080/api/lotto/bulk-results \
      -H "Content-Type: application/json" -d @-

curl -s -X POST http://localhost:8080/api/lotto/analyze-all
```

**결과**: 1~1223회차(2002-12-07 ~ 2026-05-09) 전체 1223건 저장 + 5가지 전략 분석 완료

**시퀀스 명시 추가**

**api_token singleton 버그 수정**

- 실제 DB `api_token` 테이블에 `singleton` 컬럼이 없음을 확인
- `TokenMapper.xml`이 `ON CONFLICT (singleton)` 을 사용하고 있어 토큰 신규 발급 시 에러 발생 구조였음
- `findLatest`가 `ORDER BY id DESC LIMIT 1`로 최신 행을 읽는 구조이므로 singleton 불필요
- `data.sql`에서 `singleton` 컬럼·UNIQUE 제약 제거
- `TokenMapper.xml` upsert를 단순 `INSERT`로 수정

cavecrew는 서브에이전트 출력을 caveman 압축 포맷으로 반환해 토큰을 ~60% 절감함.

**설치 내용**

| 경로 | 설명 |
|------|------|
| `~/.claude/skills/cavecrew/` | 스킬 가이드 (언제 어떤 에이전트를 쓸지 결정) |
| `~/.claude/agents/cavecrew-investigator.md` | 코드 탐색 전용 에이전트 (읽기 전용) |
| `~/.claude/agents/cavecrew-builder.md` | 수술적 편집 에이전트 (1-2파일 한정) |
| `~/.claude/agents/cavecrew-reviewer.md` | diff/파일 리뷰 에이전트 |

**설치 방법**  
`claude` CLI가 PATH에 없는 VSCode 익스텐션 환경이므로 GitHub에서 직접 수동 설치:
```bash
mkdir -p ~/.claude/agents
curl -s "https://raw.githubusercontent.com/JuliusBrussee/caveman/main/agents/cavecrew-investigator.md" -o ~/.claude/agents/cavecrew-investigator.md
curl -s "https://raw.githubusercontent.com/JuliusBrussee/caveman/main/agents/cavecrew-builder.md" -o ~/.claude/agents/cavecrew-builder.md
curl -s "https://raw.githubusercontent.com/JuliusBrussee/caveman/main/agents/cavecrew-reviewer.md" -o ~/.claude/agents/cavecrew-reviewer.md
```

**사용 패턴**

| 에이전트 | 용도 |
|----------|------|
| `cavecrew-investigator` | "X가 어디 정의됐나", "Y를 호출하는 곳 찾아줘" |
| `cavecrew-builder` | 범위가 명확한 1-2파일 수정 |
| `cavecrew-reviewer` | diff·파일 버그 리뷰 |

### 로또 시드 데이터 분리 (lotto_seed.sql)

**배경**  
다른 PC에서 코드를 받아 실행하면 `lotto_result` 데이터가 없어 분석 기능이 동작하지 않음.  
`data.sql`은 DDL 전용으로 유지하고, 초기 데이터는 별도 파일로 분리.

**신규 파일**

| 파일 | 설명 |
|------|------|
| `resources/lotto_seed.sql` | 로또 1~1223회차 당첨번호 전체 INSERT (`ON CONFLICT DO NOTHING`) |

**새 환경 세팅 순서**
```bash
# 1. 테이블·시퀀스 생성
psql -d marketpulse -f data.sql

# 2. 로또 당첨 번호 입력
psql -d marketpulse -f lotto_seed.sql

# 3. 전략 분석 데이터 재생성 (lotto_analysis_pool / lotto_analysis_result)
curl -X POST http://localhost:8080/api/lotto/analyze-all
```

`lotto_analysis_pool` / `lotto_analysis_result` (각 6115행, INTEGER[]·JSONB 타입)는  
SQL 덤프 대신 `analyze-all` 엔드포인트로 재생성하는 방식 채택.

### 로또 분석 정확도 고도화 (목표 하향: 30% → 25%)

**배경**  
기존 `analyzeOnly`가 `findRecentResults(100)` 으로 미래 데이터를 포함해 분석 → 통계적으로 무의미.  
전략 수식도 단순 빈도 기반이라 정확도 한계. 기획 문서(`lotto-final-plan.md`)의 고도화 계획 전체 구현 후 실측.

**수정 파일**

| 파일 | 변경 내용 |
|------|-----------|
| `resources/mapper/lotto/LottoMapper.xml` | `findResultsBeforeDrawNo` 쿼리 추가 (`WHERE draw_no < #{drawNo}`) |
| `domain/lotto/mapper/LottoMapper.java` | `findResultsBeforeDrawNo` 메서드 추가 |
| `domain/lotto/service/LottoService.java` | `analyzeOnly`, `collectAndAnalyze`, `insertResultManual` → `findResultsBeforeDrawNo(drawNo)` 교체 (백테스트 원칙) |
| `domain/lotto/service/LottoAnalysisEngine.java` | 전면 개선 (하단 참조) |

**LottoAnalysisEngine 최종 개선 내용**

| 항목 | 변경 전 | 변경 후 |
|------|---------|---------|
| 모멘텀 Hot | 단순 구간 합산 | 지수 감쇠 WeightedFreq (`0.95^(현재-출현회차)`) |
| 모멘텀 Rising | 단순 카운트 차이 | 지수 감쇠 구간 비교 |
| 잠수함 | Cold + Falling | Cold + Falling + DueScore (기대 주기), 가중치 0.4/0.3/0.3 |
| AI 스마트픽 앙상블 | 4개 전략 동등 투표 | SUBMARINE 제외 3개 전략(MON+NET+PAT) 투표, HOT 가중치 상향 |
| 조합 합계 | 80~170 | 100~175 (역대 당첨 분포 70% 커버) |
| 구간 커버리지 | 3구간 이상 | 4구간 이상 |
| 연속번호 | 연속쌍 ≤ 2 | 3연속 이상 금지 (maxRun < 3) |
| 폴백 | 필터 없이 전체 | 완화 조건 → 최후 폴백 (2단계) |

**시도했으나 역효과 → 롤백한 것**

- `pairRate`에 지수 감쇠 적용: NETWORK 22.6% → 22.0% 하락 (페어 관계는 장기 데이터가 안정적)
- `PATTERN` 끝수·구간 분석에 감쇠 적용: PATTERN 22.2% → 21.9% 하락 (30회 고정 윈도우가 더 적합)

**최종 백테스트 결과 (1113회차 기준, draw_no > 110)**

| 전략 | 적중률 | 랜덤(22.2%) 대비 |
|------|--------|----------------|
| MOMENTUM | **22.9%** | +3.1% |
| NETWORK | 22.6% | +1.9% |
| AI_PICK | 22.4% | +1.0% |
| PATTERN | 22.2% | ±0% |
| SUBMARINE | 21.8% | -2.0% |
| 이론 상한 (매 회 최선 전략 선택) | 38.1% | — |

**결론**  
외국 학술 연구(Stanford, arXiv) 및 GitHub 프로젝트들 조사 결과, 순수 통계 방법으로는 LSTM/딥러닝도 랜덤 기대값 수렴. 현재 MOMENTUM 22.9%가 통계적 방법의 현실적 상한에 가까움. 목표를 30% → **25%로 하향** 조정하고 개발 종료.

**새 환경에서 재분석 순서**

```sql
DELETE FROM lotto_analysis_result;
DELETE FROM lotto_analysis_pool;
```

```bash
curl -X POST http://localhost:8080/api/lotto/analyze-all
```

### 로또 조합 필터 강화 — 구간 분포 + 끝수 몰림 제거

**배경**  
실제 당첨 번호는 5구간(1~10, 11~20, 21~30, 31~40, 41~45)에 각 1~3개씩 분포.  
기존 필터는 4구간 이상만 요구해 한 구간이 아예 비어도 추천 조합이 생성될 수 있었음.  
또한 `1,11,21,31,X,Y` 같은 끝수 몰림 패턴도 걸러내지 못했음.

**수정 파일**

| 파일 | 변경 내용 |
|------|-----------|
| `domain/lotto/service/LottoAnalysisEngine.java` | `passFilter` 강화 |

**변경 내용**

| 조건 | 변경 전 | 변경 후 |
|------|---------|---------|
| 구간 분포 | 4구간 이상 | **5구간 모두 1~3개씩** (빈 구간 금지) |
| 끝수 몰림 | 없음 | **같은 끝수 3개 이상 금지** (신규) |

**현재 전체 필터 조건**

| 조건 | 내용 |
|------|------|
| 합계 | 100~175 |
| 홀짝 | 2:4 / 3:3 / 4:2만 허용 |
| 구간 분포 | 5구간 각 1~3개 |
| 연속번호 | 3연속 이상 금지 |
| 끝수 | 같은 끝수 3개 이상 금지 |

풀 적중률(%)은 필터와 무관 (풀은 전략 점수로 선택, 필터는 추천 조합 생성 단계에만 적용).
