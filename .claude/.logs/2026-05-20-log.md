#### 🔴 CRITICAL (백테스팅 결과 신뢰성 직결)

**1. Look-ahead bias — MomentumStrategy**
- 파일: `domain/quant/service/strategy/MomentumStrategy.java:25-26`
- 문제: `findTopStocksByReturn(fromDate, toDate, 20)`로 전체 백테스팅 기간의 수익률 기준 상위 20종목을 선정한 뒤 첫날부터 매수. 기간 말 기준의 미래 정보를 첫날에 참조하는 구조 — 현실에서 절대 불가능한 수익률이 나온다.
- 수정 방향: 매월 첫 영업일 기준으로 **직전 21 영업일(과거)** 수익률로 랭킹. `findTopStocksByReturn(rebalanceDate.minusDays(30), rebalanceDate, 20)` 패턴으로 변경. 전체 기간 루프는 월별로 분리.

**2. Look-ahead bias — SectorRotationStrategy**
- 파일: `domain/quant/service/strategy/SectorRotationStrategy.java:25-26`
- 문제: `findTopBySectorReturn(fromDate, toDate, 15)`로 동일한 전체 기간 미래 참조.
- 수정 방향: MomentumStrategy와 동일. 매월 첫날 기준 직전 21일 과거 데이터로 섹터별 수익률 계산 후 상위 3섹터 선정.

**3. KRX API 에러 무시**

### KIS 토큰 반복 발급 원인 정리 및 보완
- 원인 확인: `TokenMapper.xml`이 `api_token_singleton_unique` constraint 기반 upsert를 사용하지만 실제 DB에는 해당 constraint가 없어 신규 토큰 저장이 실패할 수 있었음
- Redis `API_TOKEN` 키는 만료된 토큰이 TTL 없이 남아 있어, 캐시 키 존재 여부가 아니라 `expiredAt` 기준으로 매번 만료 판정되는 상태였음
- `TokenMapper.xml`을 최신 row update + 없으면 insert 방식으로 변경해 DB constraint 불일치에 의존하지 않도록 수정
- `RedisTokenRepository` 저장 시 `expiredAt - 5분` 기준 TTL을 설정하도록 수정
- `TokenService`에 Redis/DB cache hit 및 신규 발급 로그 추가
