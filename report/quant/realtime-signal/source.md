## 결론

현재 방향은 잘못 잡혀 있었다. `KOSPI_BULL`, `KOSDAQ_BULL`는 장중 1분봉 감시 모델이 아니라 일봉 랭킹 기반 후보 생성에 가까웠고, 2026-06-01 같은 장에서는 시초가 갭, 테마 확산, 장중 거래대금 폭증을 실시간으로 못 잡는 구조였다.

수정 방향은 `1분봉 전종목 감시 -> 후보 상태 계속 갱신 -> 확정 신호만 진입 -> 진입 후 리스크/재진입 통제 -> 장마감 학습 라벨 저장`이다.

## 왜 놓쳤나

1. 후보 엔진이 전체 시장 1분봉을 보지 않았다.
   - 기존 후보는 `CHANGE_RATE_DESC` 일봉 랭킹 중심이었다.
   - 삼성전자처럼 대형 거래대금 상위, 장중 추세형 종목은 등락률 상위 소수 필터에서 빠질 수 있었다.

2. 시초가 갭/동시호가 감시가 없었다.
   - LG전자는 전일 종가 293,000원 대비 09:02 첫 유효 분봉이 369,000원이었다.
   - 이미 +25.94%로 시작한 종목이라 장중 일반 스캐너보다 `08:50-09:05 pre-open/opening gap` 감시가 먼저 필요했다.

3. 테마 클러스터 감시가 없었다.
   - LG전자 단독이 아니라 LG헬로비전, LG전자우, LG씨엔에스, LG, LG이노텍, 로보스타, 두산로보틱스, 레인보우로보틱스까지 확산된 장이었다.
   - 모델은 종목 단일 스코어만 보고 테마 자금 확산을 후보 승격 조건으로 쓰지 않았다.

4. 당일 데이터 업데이트 신뢰성이 깨져 있었다.
   - 운영 랭킹 API가 요청 날짜와 다른 과거 날짜를 반환했다.
   - 이 상태에서는 오늘 후보/어제 분석/실시간 후보가 모두 오염될 수 있다.

## 실시간 엔진 설계

### 1. 데이터 수집

- 08:50-09:00: 동시호가/예상체결, 전일 대비 예상 갭, 예상 거래대금
- 09:00-15:30: 전종목 1분봉 또는 KIS 실시간 체결 WebSocket
- 1분마다 저장: 현재가, 등락률, 분당 거래량, 누적 거래대금, VWAP, 고가 근접도, 전일 거래량 대비 속도
- 뉴스/테마: 종목명, 그룹명, 키워드, 관련주 그래프

### 2. 후보 상태

```text
NONE -> WATCH -> HOT -> ENTRY_READY -> ENTERED -> EXITED/COOLDOWN
```

- `WATCH`: 갭, 거래대금, 뉴스, 테마 중 하나 감지
- `HOT`: 1분 거래대금/등락률/테마 확산 동시 충족
- `ENTRY_READY`: 2-3개 분봉 연속 확인, VWAP 위, 고가 돌파 또는 눌림 후 재돌파
- `ENTERED`: paper/live 주문 가능 상태
- `COOLDOWN`: 당일 중복 진입 차단

### 3. 진입 신호

- 대형주 안정형: 거래대금 상위 20, 전일 대비 +3%, +5% 돌파, VWAP 위, 5분 고점 재돌파
- 테마 후속형: 테마 리더 상한가 또는 +20%, 관련주 3개 이상 동시 상승, 본주 고갭이면 proxy 종목 우선
- 장중 급등형: 갭 10% 이하, 10분 누적 +5% 이상, 분당 거래량 상위 5%, 고가권 유지
- 추격 금지: 시초 갭 +20% 이상이고 상한가 근접한 본주는 즉시 매수하지 않고 proxy/눌림만 감시

### 4. 학습 라벨

- `high_gap_limit_leader`: LG전자, LG씨엔에스, 로보스타
- `theme_spread_best_entry`: LG헬로비전, LG전자우
- `large_liquid_momentum`: 삼성전자, 삼성전자우, 삼성에스디에스
- `intraday_efficiency_breakout`: 한국비티비, 크라우드웍스, 크레오에스지
- `failed_theme_follow`: LG디스플레이, LG이노텍

## 구현 우선순위

1. 날짜 신뢰성 차단
   - 요청 날짜와 응답 tradeDate가 다르면 API가 실패하도록 막는다.

2. 1분봉 저장 테이블 추가
   - `quant_intraday_bar`
   - `quant_intraday_candidate_snapshot`
   - `quant_intraday_signal_event`

3. 실시간 스캐너 추가
   - 1분마다 전종목 또는 랭킹 상위+관심 테마 종목 갱신
   - 후보 상태를 upsert하고 화면은 polling/SSE로 갱신

4. 모델 분리
   - `KOSPI_BULL_DAILY`: 기존 일봉/지연 진입
   - `KOSPI_INTRADAY_MOMENTUM`: 삼성전자형 대형주 장중 추세
   - `THEME_INTRADAY_SPREAD`: LG/로봇형 테마 확산
   - `KOSDAQ_INTRADAY_BREAKOUT`: 갭 낮은 코스닥 장중 급등

5. 장마감 학습
   - 상한가/급등주를 라벨링
   - 실제 후보 누락 여부 기록
   - 다음 거래일 룰/가중치 shadow 반영

KOSPI 학습 핵심은 “지수가 강하면 개별도 안전하다”가 아니라, `지수 강세 + 개별 급락`을 별도 위험 신호로 보는 것이다. 특히 LG이노텍처럼 전일 테마 확산에 묶였지만 다음날 급락하는 종목은 `theme_follow_failure`로 학습시킨다.

### 모델 학습 반영

1. `downside_continuation`
   - 전일 -4% 이하 하락 후 오늘도 음수이면 반등 매수 금지.
   - VWAP, 전일 저점, 1분봉 higher-low를 회복하기 전에는 후보로 올리지 않는다.

2. `technical_rebound_watch`
   - 전일 -5% 이하 하락 후 오늘 +3% 이상 반등하면 바로 매수하지 않고 paper 후보만 허용한다.
   - 거래량, VWAP 유지, 전일 붕괴 구간 회복이 모두 필요하다.

3. `theme_follow_failure`
   - 같은 그룹/테마 리더가 강해도 개별 종목이 다음날 급락하면 테마 후보 승격을 차단한다.
   - LG이노텍, LG 같은 되돌림 케이스를 이 라벨로 저장한다.

4. `relative_weakness_pocket`
   - KOSPI처럼 지수가 강한데 개별 대형주가 크게 빠지는 경우를 별도 감시한다.
   - 지수 방향만 보고 후보를 열지 않는다.

5. `stale_data_reject`
   - 요청 날짜와 응답 `tradeDate`가 다르면 후보/시그널/학습 입력을 전부 차단한다.
   - 차트 마지막 캔들이 2거래일 이상 오래됐으면 차트 패턴 판단을 금지한다.

결론적으로 어제 놓친 건 급등뿐 아니라 급락도 같은 문제다. 모델이 실시간 1분봉, 날짜 검증, 시장 폭, 테마 확산/실패, 상대강도/상대약세를 동시에 보지 않으면 상승 후보도 못 잡고 하락 회피도 못 한다.

- `LIMIT_LEADER_NEXT_DAY_CLUSTER`: 전일 +25% 이상 또는 상한가 리더는 다음 장 클러스터 감시를 자동 생성한다.
- `FOLLOW_THROUGH_WATCH`: 클러스터 멤버가 +5% 이상이고 거래량이 붙으면 매수 전 WATCH로 올린다.
- `LEADER_PULLBACK_COOLDOWN`: 전일 리더가 다음날 음수면 추격 금지로 둔다.
- `THEME_FOLLOW_FAILURE`: 같은 테마 멤버가 -3% 이하로 밀리면 long 후보에서 제외하고 테마 약화 증거로 쓴다.
- `STALE_RANKING_HARD_BLOCK`: 요청일과 랭킹 기준일이 다르면 후보/시그널/학습 입력을 전부 중단한다.

### 긴급 구현 반영

1차 구현은 완성형 WebSocket 엔진이 아니라, 운영 API가 지금 당장 놓치는 감시 구멍을 줄이는 긴급 감시 레이어다.

- `LiveQuantPaperTradingScheduler`를 장중 10분 단위에서 1분 단위로 변경했다.
- `QUANT_LIVE_PAPER_SCHEDULER_ENABLED` 기본값을 `true`로 바꿔 별도 비활성화 설정이 없으면 장중 paper 감시가 돈다.
- 랭킹 기준일이 신호일보다 3일 초과로 오래됐으면 랭킹 기반 `BUY` 후보 생성을 차단한다.
- 현재가/등락률/거래대금 snapshot provider를 추가했다.
- LG 다음날 클러스터는 실시간 snapshot으로 `WATCH`, `COOLDOWN`, `WARNING` 후보를 생성한다.
- `WATCH`, `COOLDOWN`, `WARNING`은 paper 포지션을 열지 않는다. 실제 매수는 `BUY` 후보만 가능하다.

이 구현으로 오늘 같은 LG 케이스는 LG헬로비전/LG디스플레이가 `WATCH`로 올라오고, LG전자/LG이노텍/LG/LG씨엔에스는 추격 매수가 아니라 실패/되돌림 위험으로 표시된다.

## 모델 커버리지 결론

현재 `KOSPI_BULL`, `KOSDAQ_BULL`만으로는 모든 장에 대응할 수 없다. Bull 모델은 상승 모멘텀과 일부 거래대금 대형주를 잡는 데 맞춰져 있고, 시장이 아래처럼 바뀌면 별도 모델 또는 최소 별도 상태 엔진이 필요하다.

| 장 상황 | 기존 Bull 모델 한계 | 필요한 모델/상태 |
|---|---|---|
| 강한 상승장 | 대응 가능 | `INTRADAY_MOMENTUM`, `LARGE_LIQUID_MOMENTUM` |
| 테마 확산장 | 리더는 일부 잡지만 후속주 누락 | `THEME_SPILLOVER`, `LIMIT_LEADER_NEXT_DAY_CLUSTER` |
| 급락장 | BUY 후보를 내면 위험 | `DOWNSIDE_CONTINUATION_AVOIDANCE`, `MARKET_REGIME_RISK_BUDGET` |
| 횡보장 | 추세 모델이 잦은 헛신호 가능 | `SIDEWAYS_MEAN_REVERSION` |
| 갭상 후 붕괴 | 상승률만 보면 추격 위험 | `GAP_FADE_RISK`, `LEADER_PULLBACK_COOLDOWN` |
| 낙폭과대 반등 | 하락 종목을 전부 배제하면 반등 누락 | `TECHNICAL_REBOUND_WATCH` |

따라서 운영 방향은 단일 Bull 모델이 아니라 `시장 국면 엔진 + 여러 모델 패밀리 + 실시간 상태머신`이어야 한다. 오늘 적용한 코드는 그중 긴급 1차 레이어다.
