MP_CORE 월 5% 목표 모델 업데이트

목표 수익률을 “보장 문구”가 아니라 모델 검증 기준으로 재정의하고, 현재 baseline 점수 엔진을 월 5% 후보 선별에 맞게 조정하는 백엔드 중심 업데이트 기획.

결론

목표

20영업일 기준 후보군의 기대 월수익률 목표를 5%로 설정한다.

방식

라벨, 점수, 확률, 리스크 차단 조건을 모두 5% 목표에 맞춰 재정렬한다.

원칙

월 5%는 보장 수익이 아니라 백테스트/검증 기준이다.

현재 코드에는 targetMonthlyReturn = 0.15가 있으나 실제 signal SQL은 이 값을 사용하지 않는다. 이번 작업은 숫자만 바꾸는 작업이 아니라 모델 산출 기준을 실제 엔진과 연결하는 작업이다.

현재 문제

영역현재 상태문제
목표 수익률targetMonthlyReturn: 0.15월 15%처럼 보이지만 실제 신호 생성에 쓰이지 않는다.
라벨20영업일 forward return 8% 이상이면 WINNER사용자 목표 월 5%와 기준이 맞지 않는다.
점수위험조정 60일 수익률, 60일 수익률, 유동성, drawdown 조합수급/시장국면/공매도 같은 다음날 압력 데이터는 아직 미반영이다.
확률baseline score로 단순 산출목표 월수익률 달성 가능성과 직접 연결되어 있지 않다.
리스크고변동성, deep drawdown, 저유동성 플래그월 5%를 노릴 때 필요한 손실 제한과 과열 차단이 약하다.

업데이트 방향

1. 목표를 월 5%로 정렬

항목변경안
targetMonthlyReturn0.05로 조정
winnerReturnThreshold0.05로 조정
loserReturnThreshold-0.035 후보. 월 5% 목표에서 손실 방어를 더 엄격하게 본다.
winnerProbThreshold0.58 후보. 공격 목표지만 무조건 후보를 늘리지 않는다.

2. baseline score 재가중

score =
  0.35 * risk_adj_rank
+ 0.25 * ret_rank
+ 0.15 * short_term_momentum_rank
+ 0.10 * liquidity_rank
+ 0.10 * drawdown_score
+ 0.05 * market_fit_score

1차 구현에서는 데이터가 있는 범위 안에서 ret20d, ret60d, riskAdjRet60d, drawdown60d, tradeAmount20dAvg를 이용한다. 선물/공매도/장외 데이터는 테이블 확보 후 2차 반영한다.

3. 리스크 차단 강화

차단/감점기준 후보이유
저유동성유동성 rank 하위 25%월 5% 목표는 체결 가능성이 중요하다.
과도한 낙폭60일 고점 대비 -25% 이하반등 후보와 하락 추세를 구분한다.
고변동성60일 변동성 과다목표 수익보다 손실 변동이 커지는 후보를 제한한다.
추격매수5일 급등 + drawdown 없음월 5% 목표라도 과열 진입은 피한다.

구현 범위

백엔드

MpCoreModelDefinition, QuantCoreFeatureSnapshotMapper.xml, QuantCoreSignalMapper.xml 중심으로 라벨/점수/리스크 플래그를 조정한다.

프론트엔드

필수 변경은 없다. 기존 대시보드는 바뀐 score/reason/riskFlags를 그대로 표시한다. 필요 시 문구만 보강한다.

문서

퀀트 문서와 작업 로그에 월 5% 목표가 보장 수익이 아니라 검증 기준이라는 점을 기록한다.

주의사항

  • 월 5%는 공격적인 목표다. 후보 수가 줄어들 수 있고, 백테스트 기간에 따라 성과 변동이 커질 수 있다.
  • 현재 데이터만으로는 선물/공매도/장외 거래를 실제 score에 넣을 수 없다. 이번에는 구조와 플래그를 준비하고, 데이터 적재 후 반영한다.
  • 기존 active plan은 프론트 UX 리플랜으로 paused 상태다. 이번 작업은 별도 모델 업데이트 plan으로 진행한다.

승인 후에는 백엔드 중심으로 구현하고, verifier 단계에서 AC 기준으로 PASS/FAIL을 판정한다.
